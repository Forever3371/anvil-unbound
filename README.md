# Anvil Unbound（铁砧突破）

Minecraft **1.21.1** / **Fabric** 模组：改造铁砧，做了三件事。

| | 改动 | 说明 |
|---|---|---|
| 1️⃣ | **解除等级上限** | 锋利 V + 锋利 V = 锋利 VI，可一路合到配置上限（默认 **1000**） |
| 2️⃣ | **解除大部分附魔互斥** | 锋利/亡灵杀手/节肢杀手、四种保护、时运/精准采集、无限/经验修补、多重射击/穿透 —— 现在都能共存 |
| 3️⃣ | **花费从经验改成下界之星** | 完全不消耗经验等级，改为每次操作消耗 **1 颗下界之星**；铁砧界面**多了一个专门放下界之星的槽位** |

## 互斥：解除了什么、保留了什么

| 原版互斥组 | 现在的行为 |
|---|---|
| 剑/斧/重锤：锋利、亡灵杀手、节肢杀手、穿刺、致密、破甲 | ✅ **已解除**，可以共存 |
| 盔甲：保护、火焰保护、爆炸保护、弹射物保护 | ✅ **已解除** |
| 锄/锹/镐/斧：时运、精准采集 | ✅ **已解除** |
| 弓：无限、经验修补 | ✅ **已解除** |
| 弩：多重射击、穿透 | ✅ **已解除** |
| **靴子：冰霜行者、深海探索者** | ❌ **保留互斥**（按需求） |
| **三叉戟：激流、忠诚、引雷** | ❌ **保留互斥**（按需求；忠诚与引雷本来就能共存，这点没变） |

想改主意的话，配置里有 `keep_boots_exclusive` / `keep_riptide_exclusive` 两个开关，关掉就全解除。

## 下界之星怎么用

- 铁砧界面**输出槽右边**多了一个槽位，只接受下界之星，**容量是一组（64）**。
- **任何操作**（合并、修复、重命名）都需要槽里有 1 颗星，**取出结果时消耗掉**。
- **经验等级完全不扣**，界面左侧原来的「花费 X 级」被换成了「消耗 1 颗下界之星」。
- 槽里没星时：**合成结果照常显示，但取不出来**，左侧提示「需要 1 颗下界之星」。
- 支持 **shift 点击**快速填充：从背包 shift 点击下界之星会直接飞进星槽。
- 关掉界面时槽里的星会**自动还给你**（背包满则掉在脚边），不会被吞掉。
- 原版那条「过于昂贵」（≥40 级不能操作）的限制也不再触发——因为已经不花经验了。

> 想退回原版的等级花费：配置里 `require_nether_star=false`。

## 安装

1. Fabric Loader（≥ 0.16）+ **Fabric API**
2. 把 `anvil-unbound-1.1.5.jar` 放进 `mods/`
3. **客户端和服务端都要装**（槽位与文案是两边都参与的）

## 配置

首次启动生成 `config/anvil_unbound.properties`：

```properties
# 铁砧合并后的等级上限（原版各附魔最高只有 I~V，默认放宽到 1000）
max_level=1000

# 是否保留"冰霜行者 / 深海探索者"的互斥（默认 true = 保留）
keep_boots_exclusive=true

# 是否保留"激流 / 忠诚 / 引雷"的互斥（默认 true = 保留）
keep_riptide_exclusive=true

# 铁砧操作改为消耗一颗下界之星（默认 true，且不再消耗经验）
require_nether_star=true

# 是否注册 /anvilunbound selftest 自检命令（默认 true）
enable_selftest_command=true
```

改完重启游戏/服务器生效。

## ⚠️ 关于"能合到多少级"

模组抬高了上限，但**没有动累积惩罚**（原版另一套机制）。生存/冒险模式单次操作原本有 39 级上限——现在这条限制已经取消了（因为不花经验），所以：

- 影响合并次数的只剩**累积惩罚**（`2ⁿ-1`）与合并花费本身的数值
- 每次在铁砧上做非重命名操作，物品的累积惩罚都会翻倍增长，代价会越来越高
- 创造模式（或资源充足时）可以一路合到 1000

想让它"随便合都不心疼"，可以再放宽累积惩罚——那是独立的一项，说一声我加。

## 游戏内自检

```
/anvilunbound selftest
```

有玩家上下文时会跑完整检查：等级上限、**13 组互斥关系（该解除的已解除、该保留的仍保留）**、以及真的构造铁砧界面跑合并与星槽断言。控制台执行时会跳过需要玩家的部分并说明。

## 与其它模组共存

**Blast Enchant**（[高炉烧炼模组](https://github.com/Forever3371/blast-enchant)）：可以同时装。

两者都需要绕过 1.21.1 里附魔等级的三处 255 硬上限，为避免撞车，本模组带了一个 `MixinConfigPlugin`：
检测到 `blast_enchant` 已加载时自动跳过自己那三个上限 Mixin（对方上限 100000，够用）。已实测共存时双方自检全部通过。

**JEI**：已适配。JEI 的铁砧配方页会显示「消耗 1 颗下界之星」而不是原版的"附魔花费：X 级"。
JEI 是以 `compileOnly` 方式引用的（只用于编译期解析目标类，不打包、也不是必需依赖）；
没装 JEI 时对应的 Mixin 由 `MixinConfigPlugin` 直接跳过，连那个类都不会去碰。

## 实现原理

1. **等级上限**：`AnvilScreenHandler#updateResult()` 里 `getMaxLevel()` 只被调用两次（夹取判定与赋值），把这两处重定向成"原版上限与配置上限取较大者"。
2. **解除互斥**：同一方法里的 `Enchantment.canBeCombined(...)` 换成 `AnvilUnboundRules#canCombine`——除靴子（`#exclusive_set/boots`）和三叉戟（`#exclusive_set/riptide`）外一律放行。保留的两组仍走原版判断，所以"忠诚与引雷能共存、但都与激流互斥"这种细节不会被破坏。
3. **星槽**：构造完原版槽位后，通过 `@Invoker` 调用 protected 的 `addSlot`，追加一个 `NetherStarSlot`（只收下界之星、上限 1 颗）。用独立子类而不是索引，是为了别的模组也往铁砧加槽位时不会找错。
4. **花费**：`canTakeOutput` 改成"有星 && 有有效操作"；`onTakeOutput` 里 `addExperienceLevels` 被重定向为空（不扣经验），并在末尾消耗一颗星。
5. **界面文案**：客户端把 `drawForeground` 里的 `container.repair.cost` / `container.repair.expensive` 两个文本替换成下界之星提示。槽位背景由 `HandledScreen` 遍历槽位时自动绘制，不需要额外渲染代码。

三个 `EnchantmentLevelCap*Mixin` 负责让附魔组件真的能存到 255 以上（`Builder#add/set` 的截断、私有构造函数的校验、NBT codec 的取值范围）。
